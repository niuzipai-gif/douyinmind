🛠 技术栈详解

后端框架：FastAPI + Uvicorn

三个参考项目Jonesxq、lys2-14、via007 全部使用这套组合。一致选择，无需犹豫。自动生成 Swagger 文档（/docs），异步支持好，适合 I/O 密集的 RAG 场景（文件下载、API 调用、数据库读写）。

数据库：SQLAlchemy 2.0 + SQLite

本地零配置，个人项目最佳选择。三个参考项目全部使用 SQLite。最初设计了 aiosqlite 异步方案，但 Jonesxq 全部用同步 Session，为保持一致性改为同步引擎——SQLite 本身就是单写入者，异步收益有限。

向量库：ChromaDB

三个参考项目全部使用 ChromaDB。本地持久化、零运维、Python 原生 API。支持 cosine 距离 + MMR 检索。相比 Milvus/Qdrant，ChromaDB 更适合单机小规模场景（数千到数万条 chunk）。

LLM：DeepSeek 用户指定

用户明确选择 DeepSeek。兼容 OpenAI 协议，base_url 一切即可切换。中文能力强、价格低、速度快。对比：Qwen（Jonesxq 默认）和 DashScope 百炼（via007 默认）也是可选方案。

Embedding：DashScope text-embedding-v4 用户指定

云端方案，即开即用，无需下载模型。输出 1024 维向量。对比方案：本地 BGE-small-zh-v1.5（Jonesxq 和 lys2-14 默认，400MB 下载，512 维，零费用）。用户选择云端是看重免下载和速度。

ASR：DashScope paraformer-realtime-v2 用户指定

云端语音识别。最初尝试 Transcription.async_call + file:// 协议遇到 DECODE_ERROR，切换为 Recognition.call API 解决。对比方案：faster-whisper（Jonesxq 和 lys2-14 默认，150MB 下载，CPU 可跑，零费用）。用户明确拒绝切换到本地方案。

音频下载：yt-dlp + ffmpeg

yt-dlp 是 youtube-dl 的活跃 fork，支持抖音视频下载。ffmpeg 用于提取音频流、转码为标准 WAV（16kHz 单声道 PCM），确保 DashScope ASR 可识别。三个参考项目全部使用这套组合。

浏览器自动化：Playwright + Chromium

用于抖音扫码登录。Playwright 比 Selenium 更快、API 更现代。三个参考项目全部使用 Playwright。支持持久化上下文（保留 Cookie + localStorage）、反检测脚本（隐藏 webdriver）。

前端：React 19 + Vite + TypeScript + Tailwind CSS

Vite 比 CRA 快 10x+。Tailwind CSS 的 utility-first 方式适合快速原型。暖色系配色（奶油底色 + 珊瑚红主色 + 琥珀辅色）通过 Tailwind 配置和 CSS 变量实现，匹配 Pencil 设计稿。

🚀 技术实现路线

阶段 1：项目初始化 + 后端骨架

创建 28 个 Python 文件，FastAPI 入口 + Pydantic 配置 + loguru 日志 + 5 张数据表 ORM。参照 Jonesxq 的标准分层：core/db/models/schemas/api/services。

阶段 2：认证 + 收藏夹同步

Playwright 扫码登录 → Cookie 保存 → Webpack collects 模块 API 抓取收藏夹和视频列表 → 差异同步到 SQLite。遇到 statusCode: 8 鉴权失败，最终改为登录+抓取一体化（不关浏览器直接抓取）。

阶段 3：知识库入库流水线

yt-dlp 下载音频 → ffmpeg 转 16kHz WAV → DashScope ASR 转写 → 固定大小切块（1000字/200重叠）→ DashScope Embedding → 存入 ChromaDB。后台 worker 线程串行处理。

阶段 4：RAG 对话引擎

查询路由（问候/列表/总结/向量检索）→ 向量语义检索 → 上下文构建 + 历史对话注入 → DeepSeek LLM 生成 → 答案后处理。支持非流式 + SSE 流式双模式。完整的 ChatSession + ChatMessage 会话管理。

阶段 5：前端界面

Pencil 设计稿先行 → React 19 + Tailwind CSS 暖色系。Landing 页（Hero + 流程示意）→ 登录弹窗（QR码轮询）→ 双栏 Workspace（收藏夹+入库+对话）→ Collection Detail。双栏可拖拽分隔条，对话流式输出 + 来源引用。

阶段 6：测试 + 文档

pytest 24 个用例覆盖文本处理 + RAG 路由 + 答案清洗。README.md 完整文档。

🐛 踩坑记录

问题 1：statusCode: 8 — Webpack API 鉴权失败

扫码登录后，同步收藏夹时 Webpack collects 模块 API 返回 statusCode: 8。

根因：登录用持久化浏览器上下文，抓取时新建浏览器上下文只加载 Cookie，丢失了 localStorage。且调试过程中不慎将空登录态的 state.json 写回覆盖了有效 Cookie。

✅ 解决：登录和抓取改为同一持久化上下文中完成，不关浏览器直接抓取。

问题 2：DECODE_ERROR — DashScope 无法解码音频

DashScope Transcription API + file:// 协议返回 DECODE_ERROR。

根因：DashScope 服务器无法访问本地 file:// URL，且 yt-dlp 产生的 mp3 格式不被识别。

✅ 解决：改用 Recognition API + paraformer-realtime-v2（支持本地文件路径），并用 ffmpeg 转码为 16kHz 单声道 PCM WAV。

问题 3：Webpack no_require — 模块未加载

Cookie 注入方式切换后出现 no_webpack_require。

根因：Playwright 的 add_init_script 必须在 page.goto() 之前调用，之前放在了导航之后。且直接跳转收藏夹页时 Webpack 未完全加载。

✅ 解决：先导航到首页等 Webpack 加载，init_script 前置，刷新使 Cookie + 反检测生效。

问题 4：yt-dlp Cookie 过期 待解决

部分视频 yt-dlp 下载时报 Fresh cookies are needed。

根因：Playwright 导出到 Netscape 格式的 Cookie 文件对部分视频不生效，抖音可能对 yt-dlp 做了额外校验。

可能方案：① 用 Playwright 拦截页面直接获取音频 URL ② 升级 yt-dlp ③ 用抖音官方下载 API
